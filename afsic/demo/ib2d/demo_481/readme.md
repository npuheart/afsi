# demo_481 — IB2d `Two_Corals`（双珊瑚触手摆动：钉死目标点 + `update_Target_Point_Positions`）

IB2d 官方算例（`matIB2d/Examples/Example_Corals/Two_Corals`）。
本 demo 由**合并模板** `afsic/demo/ib2d/_template/` 用
`python port_example.py 481 Example_Corals/Two_Corals` 生成，
验证模板覆盖「钉死目标点 + 例子自带 `update_Target_Point_Positions.py`（锚点随时间运动）」
这一组合。

## 算例内容

* `0.6 x 0.6` 周期盒、`mu = 0.0025`、`rho = 1`；官方 `128 x 128`
  （`h = 0.0046875`）、`dt = 1e-5`、`T = 6`（60 万步）。
  **注意**：该算例的 `input2d` **没有 `print_dump`**，两个代码都用
  `max(1, 步数/20)` 的兜底值（本 demo 显式传 `print_dump = 50`）。
* **结构**：360 个标记点，**全部**是 `k = 1e8` 的钉死目标点（id 1…360，即 0 基 0…359）；
  没有弹簧、没有梁、没有外力。几何是两条触手（`x ∈ [0.110, 0.490]`、
  `y ∈ [0.250, 0.325]`）。
* **摆动律**（例子自带的 `update_Target_Point_Positions.m`）：保持 `y` 锚点不变，
  用 `t = 30 · mod(current_time, 2.30)` 驱动一条**分段多项式**，把每个触手点的
  `x` 锚点搬到

  ```
  X_target = xoffset + qpoly4/S - qpoly3·ξ + qpoly2·S·ξ² - qpoly1·S²·ξ³,  ξ = y_anchor - yoffset
  ```

  （`S = 1733.33`，`qpoly1..4` 由 7 次多项式系数给出），并按索引分到 4 个区域
  （±0.2 / ±0.4 的网格偏移）；`t > 2.25·30` 后用线性回插收尾。周期 2.30 s。
* 该算例的**初值本身就有跳变**：模块在 `t = 0` 给出的锚点与 `.vertex` 里的初始位置
  相差最多 ~0.2 m（`k = 1e8` ⇒ 初始罚力极大），两边代码都经历这个启动冲击
  —— 这是上游算例的行为，不是移植引入的。

## 移植要点

* `update_Target_Point_Positions.m` → `ib2d_input/update_Target_Point_Positions.py`：
  逐行移植（4 组 7 次多项式系数按 `.m` 的 `qc11..qc17` 顺序存成元组，
  `_poly()` 展开为 `t^6 … t^0`）。MATLAB 的 1 基行号 `i` 变为 `i0 = i - 1`，
  因此分支条件 `i <= N/2` / `i <= N_half` 写成 `i0 < N/2` / `i0 < N_half`；
  `targets(IDs(i),2) = ...` 对应 `targets[i, 1] = ...`（本算例的目标行就是按 id 排列的）。
* 模板把锚点保存在可变的 `target_info (N,4)` 数组里（列 = id, x, y, k），
  与 pyIB2d 驱动的 `target_info` 布局一致，更新模块直接改它；两边跑同一份 `.py`
  （pyIB2d 从运行目录导入）。
* `ib2d_io.detect_index_base()` 判定 `index_base = 1`。
* 本例只有目标点，模板的 `springs/beams/nonInv/muscles/porous/poroelastic/…` 全部自动关闭。

## **不可比较**的部分（明确声明）

1. **速度场不可逐帧比较**。本例是 `Re = rho·u·L/mu ≈ 1·2·0.6/0.0025 ≈ 480` 的
   启动冲击流，参考解自身的峰值速度在相隔 5e-4 s 的相邻帧就上下跳
   1.28 → 2.01 → 1.58 → 1.28 → 1.83（±40%，共位网格上的格点尺度噪声），
   而 AFSI 平滑（0.86 → 1.15 → 1.25 → 1.28 → 1.22）。动能比
   `KE_AFSI/KE_IB2d = 0.34 / 0.51 / 0.74 / 0.78 / 0.57`，即 AFSI 系统性地偏弱 20–65%。
   这一窗口只有 3 ms，流场远未发展成上游算例想展示的"触手摆动诱导的稳定绕流"。
   可以拿来对比的是**结构运动学**（1.4e-03 h）与**罚力/锚点**（带外 1e-14）。
2. **没有使用 grad-div 稳定化（`GRAD_DIV = 0`）**。demo_451/473/474 里 `gamma`
   修正的是 AFSI **偏强** 1.5 倍的系统性偏差；本例 AFSI 一致**偏弱**，
   `gamma` 只会让它更弱，因此不适用（也就没有做 `gamma` 扫描）。
3. **`T = 3e-3` 而不是官方的 6.0**：t 只走到 `30·mod(t, 2.3) = 0.09`，
   分段多项式的取值几乎还是 `t = 0` 的常数项，**触手几乎没有摆动**；
   本例检验的是"锚点跳变后的短时响应"，不是官方 2.3 s 周期的摆动。
   要看到完整摆动需要 `dt = 1e-5`（HF 稳定性要求）下 23 万步，远超本 demo 的规模。
4. **`multi-` 分辨率对照没有做**：官方就是 128²，本 demo 已用官方分辨率；
   再加密（256²）虽然能减轻格点噪声，但代价过大（`dt = 1e-5` 下 AFSI 每步耗时 ×4）。

## 运行

```bash
conda activate afsi-dolfinx
python run_reference.py --nx 128 --dt 1e-5 --tend 3e-3 --print-dump 50   # ~33 s
NX=128 DT=1e-5 TFINAL=3e-3 PRINT_DUMP=50 python main.py                  # ~70 s
python compare.py
```

（运行时间为单线程 `OMP_NUM_THREADS=1` 下的墙钟时间，测量时机器负载很高。
`compare.py` 写出 `figures/compare_history.png`、`figures/compare_fields.png`、
`figures/compare_profiles.png` 与 `figures/compare_table.csv`。）
