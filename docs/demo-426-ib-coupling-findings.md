## 1. IB 算子并没有被错误归一化（commit `00d7d8c` 的前提是错的）

`duality_check.py` 把 commit `00d7d8c` 的测量做了两遍：Lagrangian 侧内积 `<Iu,F>` 分别与

* 节点和 `Σ_ij u_ij (SF)_ij` 比较 → 比值精确等于 `(h/2)²`；
* 体积权内积 `Σ_ij u_ij (SF)_ij · dx·dy` 比较 → 比值等于 `1.000000`。

```
   N        h/2           <Iu,F>   <u,SF> (nodes)  LHS/RHS_nodes      (h/2)^2
  16    0.03125    -2.888303e+00    -2.957623e+03   9.765625e-04 9.765625e-04
  32    0.01562    -4.740492e+01    -1.941706e+05   2.441406e-04 2.441406e-04
  64    0.00781     7.338415e+00     1.202326e+05   6.103516e-05 6.103516e-05
 128    0.00391    -4.497689e+01    -2.947605e+06   1.525879e-05 1.525879e-05

   N   <u,SF> dx dy   LHS/RHS_vol
  16    -2.888303e+00     1.000000
  32    -4.740492e+01     1.000000

 128    -4.497689e+01     1.000000
```

demo_426 readme 引用的三个数（9.766e-04、2.441e-04、6.104e-05）**正好就是 `dx·dy`**
（`dx = 1/(2N)`）：它们是流体侧内积里漏掉的网格面积，而不是 distributor 的缺陷。
`afsic/tests/test_duality.py`（本来就带 `dx·dy` 权重）一直通过到 1e-15。
结论：`SPREAD_NORM=h2` 把 Lagrangian 力乘上 `DX² = 9.77e-4`，即把 IB 耦合削弱了 **1024 倍**。

## 2. 去掉它也不能救 demo_426：系绳路线超出了它的稳定预算

持位实验（`hold_test.py`）：关掉驱动，把板子向外偏 0.5 个 `dx`，然后观察 200 步的位移。

| 运行 | 第 1 步 | 第 5 步 | 第 10 步 | 第 20 步 | 第 200 步 |
|---|---|---|---|---|---|
| 426, `BETA=1e6`, `SPREAD_NORM=none` | 1.56e-2 | 3.30e-1 | 2.11e+03 | 3.82e+14 | — |
| 426, `BETA=1e5`, `SPREAD_NORM=none` | 1.56e-2 | 1.83e-2 | 2.50e-2 | 6.79e-1 | 3.34 |
| 426, `BETA=1e6`, `SPREAD_NORM=h2` | 1.56e-2 | 1.565e-2 | 1.566e-2 | 1.568e-2 | 1.585e-2 |
| 424, `BETA=1e7`（自身 `dt=2e-4`） | （0.5H=5e-4） | — | — | 第 100 步 7.44e-4 → 第 500 步 4.03e-4（衰减） | |
| 424, `BETA=1e7`，`dt` 换成 426 的 6.25e-3 | — | — | max\|u\|=2.4e22（第 10 步），位移 9.1e+03 | | |

* 426 **放大** 0.5 格的扰动（带 `h2` 时干脆冻住：完全没有恢复力）。
* 424 在自身 `dt` 下把同样的扰动**衰减**掉，而一旦给它 426 的 `dt` 就炸掉。同一段代码路径、
  同一个 `beta`，只改了 `dt`（31 倍）。

控制量：`beta·dt²/rho`

* 424：`1e7 · (2e-4)² = 0.4`（稳定，能压住壁面）；
* 426：`1e6 · (6.25e-3)² = 39`（炸）；`1e5 → 3.9`（缓慢发散）；
  `1e6` 再乘 `h2` 因子 → `0.038`（冻住，耦合实际上失效）；
* 426 把 `dt` 缩小 31 倍、`BETA=1e5` → `4e-3`，增长慢约 30 倍。

板厚改成 2dx/4dx、Lagrangian 网格加密（`LAGRANGIAN_DIV=4`）、`MAP_AT_REFERENCE=1`
都试过（`geom.sh`）——全部仍然发散，所以"板子只有一格厚"不是病因。

## 3. demo_426 什么配置能用（readme 里 6.76 % 那次真正用的是什么）

驱动方式 × 板子处理 的 2×2×2 对照（`sweep.sh`），320 步：

| 驱动 | 板子处理 | 通道内相对 L2 | 板面滑移 / u_max | 板漂移 |
|---|---|---|---|---|
| 体力（被忽略，见下） | 隐式 drag 带 1e4 | **0.0533** | 0.0053 | 0 |
| 入口解析速度 BC | 隐式 drag 带 1e4 | **0.0533** | 0.0053 | 0 |
| 入口解析速度 BC | 系绳 1e6 + h2 | 6.76（已发散） | 2.45 | 2.20 |
| 入口解析速度 BC | 系绳 1e8 + h2 | 2.47（已发散） | 2.00 | 3.59 |
| 入口解析速度 BC | 系绳 1e6，不缩放 | 炸 | — | — |

只有隐式 drag 带能真正按住板子：阻尼项组装进动量 LHS，因此不受时间步限制。

注意：`main.py` 里加 `USE_BODY_FORCE` 的那行位于 `if not cfg.USE_IMPLICIT_DRAG:` 块内，
所以开 drag 带时体力被静默忽略 —— 上表前两行 4 位有效数字完全相同就是这个原因。

## 4. 为什么已提交的那次运行远不止"板子漂了一点"

`inspect3.py` 分析 `plot/N32_ipcs_smoke`：板位移几乎纯**切向**（沿板均值 +8.25e-2 = 2.6 格，
法向均值 -9.4e-5），也就是说壁面那条*线*还在，板子只是被流动以 ~0.37 u_max 的速度带着走。
真正的破坏是板子完全不出力，于是**根本没有受限通道**：`outer.py` 显示通道**外**的流体
`|u|` 达到 `6.2e-2 = 0.37 u_max`（均值 1.7e-2），即入口驱动的剖面直接散进方盒里，
而不是形成通道流。通道内部剖面被压平：中心线 `|u| = 8.93e-2`，解析值 1.667e-1，
通道内真实 L2 误差 0.347（`inspect4.py`，按离板距离分箱）。所以只有"限制在通道内"的
指标才是可信的。

## 5. Fig.23 剖面采样线的测量 bug

`main.py::profile_line()` 用的是 benchmark 坐标系且漏了 `SHIFT_Y`：

```
x = 0.5*cos - t*sin ,  y = 0.5*sin + t*cos      # 过点 (0.433, 0.250)
正确：y = SHIFT_Y + (X-SHIFT_X)*tan(theta) + t*cos  # 过点 (0.5, 1.055342)
```

沿代码里那条线 `xi ∈ [-1.2413, -0.0866]`：201 个点只有 85 个在通道内，其余都在与"无界抛物线"
解析解比较（就是 readme 自己提醒过的整盒指标那种假象）。这就是报告里
`profile_relL2 = 0.74`、`u_max location = +0.5774`（正好是壁面）的来源。改为在流体节点上找
`|u|` 极大值，峰值落在中心线（`xi = -0.0028`）且数值精确。

## 6. demo_424 并非免疫 —— 它只是恰好处在能用的角落里

`d424.sh`，`T_END=0.1`，`SOLVER=ipcs`，open 工况：

| BETA | u_max 相对误差 |
|---|---|
| 1e7（原值；T=0.4 收敛值为 -4.4 %） | -8.6 % |
| 1e4（即弱 1024 倍 = `SPREAD_NORM=h2` 的效果） | **+23 %** |

也就是说 424 的壁面靠的是同一套机制，只是那个 `beta` 既足够强、又足够稳定。
按 `h2` "修正"的倍数去削弱它，424 一样会坏。
